# Camera study C

같은 4석 장면을 세 카메라로 만들었다. dev-hoodie·professor·punk-girl·red-braid가 앉고 beanie-scarf가 걷는다. 네 개의 목제 책상과 CRT, 청록 의자, 화분 하나, 목제 창문과 두 절개 벽이 있다. 비교 그림의 current flat도 기존 스프라이트로 같은 장면을 다시 배치했다. 앱 구현은 하지 않았다.

1번은 sprite-gen/Codex로 전경을 생성했다. 2번은 같은 CLI에서 180초 제한으로 두 번 실패해 이 세션의 imagegen 도구로 만들었다. 원본 인물 접촉 시트, env2 미리보기, 위치 가이드로 외형을 맞췄고 2번은 1번도 참조했다. 3번은 생성이나 다시 그리기 없이 기존 바닥·가구·CRT·의자·화분을 최근접 회전/전단했다. 벽은 기존 navy 타일을 수직 면에 매핑하고 인물은 원본 프레임을 똑바로 세웠다.

각 시안은 **480×300 native → 960×600, 정확히 2배 최근접 확대**다. 비교 그림은 **3840×860**으로 네 장면을 한 줄에 놓았다. 환경색은 env2/env5 팔레트, 피부와 분홍 머리 등은 선택한 원본 인물의 RGB를 사용했다. 생성 전경을 native 격자로 줄이고 기존 RGB에 맞춰 색과 알파를 정리했다. 태그는 5×7 픽셀 글자와 원·별·마름모 중립 아이콘이다.

| 안 | 출력 타일 / native 타일 | 인물 기준 셀, native | 발 앵커, native |
|---|---|---|---|
| strict 2:1 | 64×32 / 32×16 | 32×64 | (16,63), 아래 중앙 |
| steep | 64×40 / 32×20 | 36×72 | (18,71), 아래 중앙 |
| rotated top-down | 64×32 / 32×16 | 원본 32×64, 회전하지 않음 | (16,63), 아래 중앙 |

10×10 타일 방에서 strict/cheap 투영은 `x=240+16(u-v), y=100+8(u+v)`, steep는 `x=240+16(u-v), y=62+10(u+v)`다. 기울기는 26.565°와 약 32.0°다. 책상 좌표는 (3,3), (7,3), (3,7), (7,7), 화분은 (1,8), 걷는 인물은 (8.5,1.5)로 고정했다. 셀은 배치 기준이며 생성된 전경은 인물·책상·의자가 붙은 콘셉트 덩어리다. 앉기는 의자 바닥 접점, 걷기는 불투명 실루엣 아래를 바닥에 놓았다. 실제 프레임별 발·의자 앵커는 재확정해야 한다.

- **strict:** 앉은 얼굴·손이 읽히고 태그와 위쪽 호버 툴팁 자리를 잡기 쉽다. 전체 방향별 아트 재제작이 필요하다.
- **steep:** 큰 얼굴과 깊은 책상이 좋지만 태그·툴팁 자리가 빽빽하다. 전체 재제작에 큰 셀과 가림 조정이 더해진다.
- **cheap:** 원본 얼굴과 수평 태그는 읽힌다. 일괄 변환은 빠르지만 CRT·의자·화분이 누워 보이고 시선과 가구 방향이 맞지 않는다.
- **현재 flat:** 원본 앉기 품질을 유지하고 태그·툴팁 공간이 편하다. 카메라 변환 비용은 없다.

이 작은 방에서는 strict가 가장 균형이 좋다. 생성안은 같은 머리·옷·색을 유지하지만 손·안경·CRT 크기의 세부 픽셀은 원본이나 두 시안 사이에서 완전히 같지 않다. 바닥·벽 투영은 수치로 고정했고, 생성 가구 모서리는 추가 방향 검수가 필요하다. 툴팁 판정은 정지 그림의 여유를 본 판단이며 실제 UI 테스트는 아니다. 이 합성 이미지를 그대로 런타임 스프라이트로 잘라 쓰기에는 부족하다.

전체 전환은 아래 정도로 잡겠다. **strict, 최대 4개 생성 lane, 아트 지시·선택·픽셀 정리·접지/가림 검수 담당자 1명** 기준의 계획 범위다. 측정한 생산 속도나 견적은 아니다. 인물은 25명 × 약 20개 방향/행동/앉기 행 × 행당 4프레임을 가정했다.

| 종류 | 가정한 제작량 | 사람 작업 시간 |
|---|---|---|
| 바닥 | 12–20 재질의 경계·코너 포함 약 40–80 타일 | 8–16시간 |
| 벽·창·문 | 20–30 모듈 × 두 수직 면, 약 40–60장 | 12–24시간 |
| 가구 | 약 200개 × 4방향 = 약 800장 | 110–200시간 |
| 인물·앉기 | 25명 × 20행 × 4프레임 ≈ 2,000프레임 | 125–250시간 |
| 반려동물 | 6–10종의 방향별 idle/walk, 약 48–80행 | 16–32시간 |
| 작은 소품·추가 상태 | 30–50종의 별도 상태; 위 200개 기본 가구와 중복 제외 | 12–24시간 |
| 주변 애니메이션 | 10–15종 × 4–8프레임 ≈ 40–120프레임 | 16–32시간 |
| **합계** | 지시·선택·정리·방향/접지/가림 검수 포함 | **약 299–578시간** |

하루 8시간, 주 5일이면 약 **8–15주**다. 4 lane은 생성 대기를 겹칠 뿐 공통 검수 시간까지 4로 나누지는 않았다. steep는 제작 수는 같지만 셀과 가림 조정에 약 10–20%를 더 잡겠다. cheap 자동 변환 시안은 약 **1–3인일**로 예상하지만 제품 품질에는 원본에 없는 옆면과 대각선 앉기를 새로 그려야 한다. 앱 코드·깊이 정렬·태그/툴팁 UI·런타임 검증은 이 시간에서 제외했다.

실제 제작에서는 바닥 경계, 두 면의 벽·창·문, 가구 네 방향의 위/옆면과 CRT 앞뒤, 대각선 이동·작업·앉기, 동물 방향 행, 소품 상태, 반복 애니메이션을 다시 만들어야 한다. 기존 red sofa, blue carpet, checker pantry, 책장, TV/play 표시, 커피 머신, 워터 쿨러, 자판기, 아케이드, 어항도 같은 규칙으로 전환한다. 이번 4석 장면에는 이 추가 가구를 넣지 않았다.

PNG 크기·정확한 2배 픽셀 블록·기존 RGB 사용·타일 투영을 확인하고 최종 네 패널을 육안 검수했다. 생성 원본·프롬프트·보고서·합성 스크립트·검사 기록은 git-ignored `runs/C/`에 있다. 사용한 프롬프트는 `runs/C/prompt-strict.txt`, `runs/C/prompt-steep-active.txt`다. 구현이나 커밋은 하지 않았다.

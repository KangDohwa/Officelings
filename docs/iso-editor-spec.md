# Isometric office editor contract

Status: integration contract 1.1, merged implementation base `9cec3a9`. Section numbers and rule IDs are stable. Supervisor-approved additive APIs are listed in §7.5. [Lane ownership](iso-editor-lanes.md) is part of this contract. Skipped tests remain unverified acceptance criteria.

## 1. Scope and terminology

The editor supports placing, moving, rotating, deleting and duplicating floor objects; designating agent work positions; importing local custom furniture; and placing/moving/deleting/duplicating complete rear-wall decorations. It runs only in `--view iso`. Search covers every logical furniture family in the active merged pack, including desks, chairs, computers, sofas, TV, shelves, plants, lamps and rugs. A render part is never a separate palette object.

The room remains **10×10**. Floor painting, zones, door relocation, resize, interior walls, automatic cutaway, multi-seat desks, end profiles, custom actor/pet/seat rigs, cloud sharing and tracker iso export are outside this version. Fixed geometry avoids changing wall spans, floor transitions, spawn and navigation simultaneously. Existing non-10×10 iso files remain loadable by the runtime but cannot enter this editor; report L002. Never clip objects to fit.

Authority: [iso-spec](iso-spec.md) §§2, 4–6; [S0](iso-slice-s0.md); [integration contract](iso-integration-contract.md); [furniture convention](../assets/art/iso/furniture/furniture-part-convention.md); [seated occlusion](iso-seated-occlusion.md); [art pipeline](art-pipeline.md); and applicable snapshot/save/input conventions from the [flat editor](editor.md). There is no `docs/furniture-part-convention.md` at this base; the linked asset document is the actual file. Current runtime/art revisions override historical measurements in that convention as recorded in §10.

| Term | Meaning |
| --- | --- |
| Asset | Locally resolved family ID and authored state/rotation variants, e.g. `iso/desk` or `user/test-crate`. |
| Instance | Stable layout ID, asset ID, integer minimum occupied cell-center origin, rotation and state. |
| Part | Authored clip mask with ground depth anchor, tie rank and optional seat group; belongs to an instance. |
| Assembly/root | Desk plus every chair/computer instance whose `deskId` names that desk; one command/history step. |
| Work position/designation | One enabled canonical desk front seat; semantic reservation ID equals desk instance ID. |
| Approach | Walkable integer chair tile where an agent arrives; distinct from projected pelvis/hand pixels. |
| Contact | Ground/visual point derived from the authored profile, never guessed from sprite bounds. |
| Draft | Editor snapshot, possibly invalid for navigation. The live office retains its last fully valid layout. |
| Wall host | Fixed undecorated rear wall edge; decoration instances inherit its face, edge and pass. |

## 2. Schema and persistence

### 2.1 Additive source schema

Root `version` stays **1**, as required by iso-spec/S0. Add `editorVersion:1` and `workSeats:[...]`; add nullable `assemblyId` only to wall attachment segments. Existing `IsoPlacement.DeskId` links both chairs and computers, without adding another parent field. The C# additions are trailing optional parameters in `IsoLayout.cs`. No flat schema or tracker payload changes.

Editor saves require `view:"iso"`, `projection:"iso2to1"`, `tileSize:16`, `tile:{width:64,height:32,anchor:{x:32,y:16}}`, `wallRise:16`, `wallHeight:48`, `cutaway:"rear-two-walls"`, and `requiredCapabilities:["iso2to1","renderItemsV1","isoEditorV1"]`. `tileSize` is the legacy navigation value, never the projected diamond width. Older binaries reject `isoEditorV1`; they must not silently activate disabled seats. New loaders accept the two old capabilities and the editor capability. A new capability describes required behavior; it does not raise root version.

```json
{
  "editorVersion": 1,
  "workSeats": [
    {"id":"desk-1","deskId":"desk-1","chairId":"chair-1","computerId":null,"profile":"front"}
  ]
}
```

This fragment extends a complete layout. `computerId:null` means the desk's embedded, authored computer. `workSeats:[]` means no agent work positions. With **both** editor fields absent, infer all `iso/desk` front seats using their existing linked chairs and desk IDs; preserve current runtime behavior. The editor copies and materializes those designations in memory without writing the input. If a legacy desk has no canonical chair, runtime legacy loading still works, but editor validation reports L010 until a chair is linked. Missing `workSeats` with `editorVersion:1`, either editor field without its required capability, unsupported editorVersion, or editor capability without editor fields fails L001. Do not interpret an explicit empty list as legacy.

Contacts, approaches, widths, heights, agent IDs, assignments and camera state are not added to the saved seat record. Optional existing placement `orientation/width/height` must agree with the selected variant; update them only if originally present. IDs are case-sensitive, ordinal, nonempty, at most 96 characters; new IDs use ASCII letters/digits/hyphen, monotonically numbered `object-N`, `desk-N`, `chair-N`, `computer-N`, `decor-N`. Probe against all current/history IDs before allocation. Consumed numbers need not be reused after Undo. Generated part IDs and asset namespace separators are distinct from instance IDs.

### 2.2 Resolution, Save and reset

The app root is `%LOCALAPPDATA%\Vibedotcom`; editor layout is **`iso-layout.json`**, backup `iso-layout.json.bak`, user object catalog `iso-objects\catalog.json`, immutable object directories `iso-objects\objects\<sha256>\`. Flat continues using `layout.json` and its existing flat pack/user folder. `IsoEditorPaths.RootDirectory` is supplied by AppStorage, never discovered inside Core. Demo/QA/tests use an isolated synthetic worktree root for both reading and writing. No background directory watcher is required.

Startup loads the embedded iso pack, verifies the local catalog, merges complete validated objects, then loads/aggregates validation of `iso-layout.json`. If the user file is absent, use the bundled **twelve-seat** `pack.Layout` (fallback `IsoTwelveSeatFixture.OfficeLayout`), not the historical three-seat `IsoLayoutLoader.Default`. Invalid user layout or missing referenced custom objects produces listed diagnostics and a complete bundled fallback; retain the original file and backups untouched. An invalid installed object is excluded with O issues; if a valid user layout does not reference it, that layout can still load. If the entire pack merge fails, use the bundled pack/layout. Never silently substitute a missing object within a layout. `assetPackId` in historical examples cannot direct a download or arbitrary file read; this version uses the explicitly supplied local pack only. Existing `--assets` remains explicit local input; `--layout` still requires flat.

Save aggregates every independent issue first, then serializes compact UTF-8 JSON and checks the **4,194,304-byte** limit before making directories or opening any output. Errors block Save; warnings are displayed but do not require acknowledgement. Use the existing local output guard (including provider-source rejection), a unique sibling temporary, flush, and `File.Replace(temp,destination,destination+".bak")`; first save uses an atomic same-directory move. Clean temporary files after failure. I/O errors return C009 and do not mark clean or claim success. Save preserves the editor snapshot/history, writes no agent reservations and creates no undo step. Successful Save updates only the saved content baseline; undoing back to identical saved content clears IsDirty.

ResetDefault is one undoable replacement with the active bundled twelve-seat geometry and inferred/materialized seats, preserving the current merged pack. It does not remove the catalog or user file. Explicit Save persists the reset. Leaving edit mode retains valid unsaved edits for this app session; a later launch requires Save. This follows the flat editor convention without adding a discard dialog. View switching keeps a valid iso session layout/history in the iso session holder; an invalid draft is retained there while live view uses the last valid snapshot. Flat/iso switch can recreate a view as today; entering/leaving editing within iso must retain actor identity (§3.3).

## 3. Objects, links and work positions

### 3.1 Floor instances and the computer adapter

Place(`iso/desk`) creates an undesignated desk with its embedded computer. The user places a canonical `iso/chair` at its approach, then the seat tool links and enables the position in one edit. This allows choosing an independently placed chair. Unlike flat Place, iso Place does not invent a chair. Existing/default linked chairs remain physical furniture even after ClearSeat. Place(`iso/chair`) creates a standalone chair without a seat; imported computer objects are ordinary standalone props without a seat. Neither a lone chair nor a lone computer is an agent work position.

Objects lane supplies a virtual built-in **`iso/computer`** palette/pack adapter by referencing the current desk's monitor housing/status parts and screen/glow, unchanged PNGs/anchors/depth. Retain their original PartIds so Core obtains the suppression set from the matching adapter variant without an objects implementation dependency. Keyboard/mouse remain desk structural parts. Adapter uses the desk variant's footprint and origin, `blockedCells:[]`, layer 1, height 40, kind `computer`; rotations match **desk orientation**, not worker facing. It has no points or seat profiles. Standalone placement renders this authored computer as an unassigned prop; it does not infer a table or a seated worker. `Place(...,hostDeskId)` is available only for this built-in adapter: origin/rotation must exactly match the desk; one computer slot per desk. A mounted instance suppresses the matching embedded monitor/status/screen/glow in scene construction, preserving keyboard/mouse and structural desk strips. Detaching/removing a designation does not suppress desk structure. Custom furniture cannot replace this rig or carry `deskId` in this slice.

`SetSeat(deskId,chairId,computerId?)` requires `iso/desk`, `iso/chair`, and either the embedded computer or mounted `iso/computer`. A standalone chair is linked only when already at the exact approach and worker-facing rotation; the command never moves it implicitly. Likewise an explicit computer must already have matching desk origin/rotation and no conflicting owner. The command atomically sets links and one designation whose Id equals deskId. A desk's existing different linked chair/computer causes C004; delete/move the complete group or choose its current parts first. No child can belong to two desks. A non-designated desk can still have linked parts. `ClearSeat` removes only the designation and retains links; linked parts always operate as an assembly. Deleting any linked part resolves to the root and removes the complete group, as in the flat panel.

For desk rotation 0/90/180/270, approach offsets are `(1,0)/(1,1)/(-1,1)/(0,-1)` and worker/chair facings are `nw/ne/se/sw`. `IsoContacts.Desk` is authoritative for approach, ground, pelvis and hands. Chair rotation is `IsoGeometry.Rotation(workerFacing)`. Contacts cannot be dragged, customized or rotated by applying the flat clockwise seat-override formula. Monitor follows desk orientation. At most **12 enabled work positions**, one per canonical desk, all reachable with occupied seats. Custom desks/chairs can be decorative objects; marking them as work positions reports C004 because no validated character-specific chair sandwich is available.

### 3.2 Wall attachments

Hosts, door, windows built into hosts, corner/end trim and rear cutaway are fixed. Only compiled modules with non-null `Slot` appear in the wall palette, grouped as complete definitions. At this base, a logical definition is the ordered contiguous `...-edge-0..N` module run from `WallModules`; remove the final `-edge-N` to obtain the logical asset ID. This deterministic adapter recovers the compiled wall-decor assemblies without runtime access to artist source folders. Plain hosts accepting an attachment are identified by the existing module rules; `HostModule` takes precedence for closed-door nameplates. Face-specific variants are distinct palette entries; wall Rotate reports C003.

Every attached edge has the same non-null `assemblyId` for that logical instance and its own unique segment ID. HostId names the fixed host for that edge. Two-edge windows use adjacent hosts along +j on left or +i on right, one slot per host, with no partial placement. For legacy bundled attachments, infer a complete contiguous module run and materialize assemblyId in memory. A one-edge attachment is a one-edge assembly. Incomplete runs fail L016. Picking any edge selects the assembly. Delete, MoveWall and DuplicateWall operate on all edges together. No change to host collision or open-door navigation accompanies decoration placement.

### 3.3 Runtime reservations and reload

Core supplies `IIsoEditorRuntime.ApplyEditorState` and `UpdateEditorPack` on the existing IsoOffice; keep IIsoOffice/Scene API unchanged. It applies only fully valid editor layouts, returns all blocking issues for invalid drafts, and never recreates the tracking service, actor/design assignments, elapsed clock or independent blink/pet RNG streams. Rebuild layout/part/nav caches only on content or pack revision. Palette import preflights editor/history and live-layout references, then uses the same pack instance for office, editor and sheet source after a successful merge; keep existing actors' design IDs. A failed pack preflight leaves all three consumers unchanged.

Reservation key remains desk/seat Id. Move/Rotate/Undo/Redo retain IDs, so returning agents retain their seat. Preserve current ownership for existing designations, including away/Gone actors until their normal exit/fade release; do not reshuffle everyone by ordinal seat sorting after each edit. Duplicate creates a new unreserved desk/seat ID. Delete/ClearSeat explicitly removes that seat and releases its reservation; remaining seats retain owners. Displaced agents stand/queue on reachable free cells and acquire an unreserved seat in ordinal agent-ID and seat-ID order. Undo restores layout/seat IDs, not a deleted live ownership assignment; no agent data exists in history or JSON.

For an edited occupied desk, finish its authored raise sequence against the current live rig, then retreat to a shared walkable/reachable tile before swapping geometry. A valid edit that would newly block a walker/pet similarly retreats through the **old** navigation graph to the nearest tile walkable/reachable in both old and new layouts (Manhattan distance, then X/Y ties). Keep the whole old live layout until affected actors have safely raised/retreated; then atomically swap cached geometry/navigation and replan to new approaches. No walker route or pet route crosses a new blocker after the swap. Hit tests/ghosts use the current editor document, and UI shows “Applying edit” while live IsoOffice.Layout is the previous snapshot. A newer accepted edit replaces the pending candidate, retaining any raise already in progress and recomputing a safe retreat; an invalid draft cancels the pending swap and leaves the current live layout running. Old and new rigs are never mixed in one world queue. This transition adds no saved instance and retains clocks/designs. Core must test pending edits as well as the final scene.

## 4. Commands and history

### 4.1 Command semantics

Expected user errors return IsoEditResult/Issue; no expected command error escapes as an exception. Result State is always the owned current snapshot. Succeeded means the command was accepted; Changed means document content changed. PrimaryTargetId selects the new/existing root or decor assembly, including a newly mounted computer's desk root. An accepted navigation-invalid draft has Succeeded=true and Error issues; runtime receives it to cancel pending publication, and Save rejects it.

Every mutation builds one candidate, aggregates §5, rejects structural errors L001–L011, L015–L017, L019 and all C preconditions without altering snapshot/history, and permits only navigation errors **L012–L014, L018** in a draft. Invalid candidate preview is still returned for a red ghost. Validate/Save/runtime reject every Error. Dependent checks on an unknown variant/ID are suppressed rather than throwing; unrelated checks continue. Constructor retains a deep-copied invalid draft for Validate; editing a legacy wrong-size document reports L002.

| Command | Action, preconditions and failure IDs |
| --- | --- |
| Place(asset,origin,rotation=0,state=default,host?) | Exact asset/state/rotation required (C002/C003); do not choose another variant. Floor asset only. Make one fresh instance ID; desk has no enabled seat until SetSeat. Optional mount obeys §3.1 (C004/C006). Check complete candidate footprint, occupancy and links (L004–L011/L017/L019). |
| Move(id,origin) | Resolve furniture or linked child to root (C001); translate root and linked computer; recompute canonical chair at new approach. Same origin is no-op. Wall IDs require MoveWall (C005). Bounds/occupancy/links apply to all members. |
| Rotate(id,rotation?) | Resolve root (C001). Explicit rotation must be authored at current state; null cycles distinct numeric rotations ascending with wrap. Fewer than two when cycling, wrong angle, absent state/linked variant: C003. Keep root origin; choose exact new dimensions/contacts/parts. Chair faces worker, computer faces desk. No source pixel transforms. |
| Delete(id) | C001 for unknown target. Resolve linked part to desk; remove root, all child links, designation. For wall attachment IDs or assemblyId, remove every attached edge. Fixed host/trim IDs: C005. |
| Duplicate(id,origin?) | Resolve furniture root (C001). Default is `(root.X+currentFootprintW,root.Y)`; no search or clipping if invalid. Copy complete assembly and enabled designation with fresh remapped IDs; preserve asset/state/profile. Run Place geometry checks. Wall target requires DuplicateWall (C005). |
| SetSeat(desk,chair,computer?) | All IDs must exist (C001), types/owners/contacts match §3.1 (C004/L009/L010); counts/uniqueness L011. Existing identical designation is no-op. Null computer selects embedded art; never allocate a runtime agent. |
| ClearSeat(desk) | Desk must exist and be canonical (C001/C004); absent designation is no-op. Keep chair/computer links. |
| PlaceWall(asset,host) | Complete logical wall definition exists (C002); all required hosts exist, faces/slots/mounts match and are free (C005/L016). Allocate one assemblyId and one segmentId per edge. |
| MoveWall(id,host) | Resolve complete decor assembly (C001/C005), preserve IDs, recompute all HostIds/edges at same face; exclude original members when checking occupancy. Identical hosts are no-op. |
| DuplicateWall(id,host) | Same checks as MoveWall; explicit destination required; remap assembly/edge IDs. |
| Undo / Redo | Empty stack reports C007. Restore one complete document; advance revision; recalculate validation/dirty. Never restore agents or catalog installation state. |
| ResetDefault | Replace with §2.2 default as one step; identical content is no-op. Catalog/pack unchanged. |
| Validate / Preview(command) | Pure: aggregate issues / construct exact mutation candidate plus §6 markers. No ID consumption, I/O, history or reservations. |
| Save(path) | C008 when draft has Errors (return those Errors too); size/output guard before any write; C009 on I/O failure. No history step. |
| UpdatePack(pack) | Transactionally retain current and history asset references; O010 on limits, C006 on unresolved reference. No layout/undo step; rebuild palette and emit Changed=false result, increment revision for a changed pack. |

### 4.2 Snapshot ownership

Copy constructor input, all nested lists/dictionaries and catalog metadata; expose immutable/read-only owned collections. Snapshots cover placements, links, wall assembly IDs, WorkSeats, tiles, zones, door and schema/capabilities. One accepted content-changing command is one undo step. Rejected commands and no-ops do not change revision, IsDirty or redo. A new accepted edit clears redo. Undo/Redo monotonically advance revision (do not restore an old revision number). History is capped at **100 undo snapshots**, dropping the oldest only after a successful edit. Pack updates require history references to remain resolvable; catalog removal cannot invalidate Undo.

## 6. Hit tests and ghosts

Coordinates passed to Core are **native scene pixels** (same space as IsoDrawItem). UI removes the current physical camera/DPI/zoom transform exactly once. `PickTile` subtracts the builder's native Camera, applies `IsoGeometry.Inverse/Snap/Owns`, rejects out-of-bounds/void; half-open ownership resolves shared edges. Ground placement never inverses an elevated sprite's top pixel.

`IsoHitTest.HitTest` scans the **supplied authoritative scene list in reverse order**, not a re-sort of numeric Depth; footprint/support ordering can make encoded Depth nonmonotonic. Editor UI obtains that scene from `IIsoEditor.GetPickingScene(camera)` for the current draft, including invalid or runtime-pending drafts. It never combines a new draft with stale live furniture. Test exact decoded source clip alpha with effective alpha `sourceAlpha*item.Alpha >= 32*255` (same as IsoPack.Opaque). Skip floor/shadow, actor/pet/labels/ghost/handles and authored HoverPassthrough; opaque fixed walls stop a search. Use layout/pack part metadata for passthrough and target ownership, not alpha bounding-box guesses or `InstanceId.Split('/')` heuristics. Linked chair/computer targets resolve to root; wall edges resolve to assemblyId. Foreground furniture without a target blocks lower hits. UI hit handles win before Core selection.

Preview computes the same candidate and validation as dispatch without committing. Show union of rotated **diamond footprint cells**, blocked cells hatched, approach points, seat ground, pelvis and two hands from canonical contacts and every authored interaction point. Green outline `#2E7D32` plus check and “Valid” for no Errors; red `#B3261E` plus cross and first rule/message for Errors; warnings amber `#8A5A00`. Navigation-invalid candidates are red with “Draft only; live office unchanged”, and can still be committed if only permissive rules fail. UI never relies on color alone. Ghost art uses the selected authored clips at 50% preview opacity without changing source bytes; it is an editor overlay, not a new world depth offset. Current document remains visible until a commit; invalid draft geometry is overlaid on the last valid office. Suppress repeated markers when no pointer/camera/selection/document change occurs.

## 7. Local custom object contract

### 7.1 Authoring shape

Input is one **local directory**, one `<id>.iso.json` manifest and its relative PNG sheet files; no archives/downloads. Use furniture-v3 `version:1`, `projection:"iso2to1"`, `sheets` and `furniture[].variants` shape. Add required `customObjectVersion:1`, `id:"user/<slug>"`, `displayName` and `palette:["#RRGGBB",...]`. Exactly one furniture family whose Id matches manifest Id. Slug matches `[a-z0-9][a-z0-9-]{0,47}`; displayName is printable, 1..80 characters. Sheet IDs must start `user/<slug>/`; local part IDs follow `<slug>__<role>__<facing>__<nn>` and remain stable across states. No references to another custom or built-in sheet.

Sheets specify id/kind (`furniture` or `shadow` only), file, cellW/cellH, integer anchor, scale:1, projection, rows. Clips specify name, direction se/sw/ne/nw/any, row, column(default 0), frames, fps, loop, partId, depthAnchor and isoZOrder; optional clip anchor overrides the sheet anchor. Each nonempty clip has a physical anchorChecks texel/radius 0 or 1. Parts name sheetId/animation/direction/partId/depthAnchor/isoZOrder, optional anchor/anchorChecks/supportRank/opacity/frame. Require agreement with referenced clip where both fields are supplied; do not use zero as “field absent”. No aliases, blink/characters, phaseContacts, seatGroupId or externally chosen hitTargetId in user content. Runtime supplies instance hit targets.

Variants specify numeric rotation 0/90/180/270, matching IsoGeometry orientation, state, footprintW/H, explicit blockedCells, finite **`height`** (source authoring field, mapped once to runtime HeightPx), parts, layer 0 or 1, optional shadow and points. Kind is `prop`, `desk`, `chair`, `computer`, `sofa`, `shelf`, `plant`, `lamp` or `rug`; these labels do not grant work-seat capability. Floor layer 0 requires height=0 and empty blockedCells. Other nonblocking furniture is allowed. Points use the existing IsoInteraction authoring fields but cannot declare typing/seat actions or custom seated contacts; only existing non-seat interaction actions accepted by the runtime may be used. Static decorative props can use `points:[]`.

Rotations are independently authored variants; a one-rotation object is valid but R reports C003. Do not rotate/mirror/repaint/crop/rescale/recenter images or synthesize missing rotations. Optional shadows are separate descriptors/sheets with explicit anchors and ground depth. A solid single-cell prop can have one mask; long furniture needs disjoint depth parts. Part masks reconstruct the static object without duplicate opaque texels; shadows are separate and may overlap it. Pixel geometry/appearance approval beyond verifiable metadata remains user content, not a claim that arbitrary custom art matches the hero.

O008 errors reject import; its warnings do not. Frozen ramp membership is exact against the existing approved environment palette (no tolerance increase); material/light/proportion matching is a visual warning/review task. No alpha or color is silently altered. Verifiable security/geometry failures list all independent reasons and reject the whole object without crashing App. Diagnostic paths and arbitrary manifest text pass existing privacy redaction; no task/session/user-profile data is included.

### 7.3 Installation and identity

Validate/read bounded bytes once; compute lower-case SHA-256 over the **original UTF-8 manifest bytes** (no BOM), prefixed with their UInt64 little-endian byte length, followed by each sheet sorted by ordinal sheet ID: UTF-8 ID length as UInt32 little endian, ID bytes, PNG byte length as UInt64 little endian, PNG bytes. No Unicode, numeric-token, whitespace or PNG normalization occurs. This deliberately makes source byte changes, including a filename or formatting change, a different content version; exact reimports are idempotent. The fixture index publishes an expected hash for the valid object so Python and C# must agree.

Before any output, preflight O010 using the original built-in pack supplied in IsoCustomImportRequest plus the current catalog and new candidate. Never pass an already merged pack as BuiltInPack. Stage a private sibling directory under `iso-objects`, copy the exact original manifest bytes to `source.iso.json`, copy each PNG unchanged to `sheet-<png-sha256>.png`, write `object.iso.json` with only sheet file references changed to those hash names, and produce deterministic `thumbnail.png` (128×128 nearest-neighbor preview, checker backdrop, authored rotation0 or lowest rotation at default or first ordinal state). Source JSON is hashing/provenance data only; never resolve its original filenames at runtime. LoadCatalog recomputes the content hash using source bytes plus installed sheets keyed by ID, and requires object.iso.json to be semantically identical except for the exact derived file references. Thumbnail is derived display data, never a world sheet. Flush/validate stage then atomically rename to `objects/<hash>` and replace catalog with backup using the existing output guard. Catalog format `{version:1,objects:[{assetId,contentHash}]}`; paths/manifest/thumbnail are derived by LoadCatalog, not trusted catalog absolute paths. Never persist the user's absolute source path. If final directory already exists, validate it against hash; do not overwrite it.

Publish directory before catalog so readers never observe missing installed sheets. On failure before catalog commit, original catalog remains authoritative; remove newly staged/published unreferenced data when safe. A leftover orphan after interrupted cleanup is harmless, absent from catalog, and reported on explicit maintenance; startup never writes or auto-deletes. Cancellation before commit behaves as failure. Reimport identical object returns success/current catalog without writes. A changed object with the same ID fails O002 rather than silently replacing layouts/history.

### 7.4 Catalog/pack merge and removal

The objects implementation uses only its public contracts plus existing pack types; it does not depend on IsoEditor private state. Merge copies validated runtime furniture/PNG/mask data into a **new pack** while retaining built-in characters, wall modules, original compiled chair-frame bindings, source palettes and Core/shared UI sheets exactly once. Never rerun the source pack builder or regenerate embedded art. Map source height to HeightPx; preserve every authored part field including explicit zero ranks. Preflight combined manifest byte/count/decoded budgets, not only a new object's budgets. Bad installed entries yield listed O issues; no partial installed object becomes visible. If a merge fails, caller retains its previous pack.

UI combines `ReferencedAssetIds` from editor history/draft with last-valid runtime, saved layout and backup references; inability to read a persisted reference file blocks removal conservatively. Remove atomically drops an unused catalog entry, then cleans only its unreferenced hash directory after handle/readers permit it. Cleanup failure reports an O009 Warning and leaves inert files; never follows a link or deletes source artist files. Built-ins cannot be removed. Undo layout operations do not undo file installation/removal. Import is available while editor is open; serialized importer transactions prevent concurrent writers.

### 7.5 Approved integration additions

`ValidatePreview(path, CancellationToken)` returns immutable `IsoCustomValidationPreview`: validated display name, authored variant count, thumbnail PNG bytes, source identity hash and issues. Its opaque capture retains the exact validated manifest/PNG bytes. The trailing optional `IsoCustomImportRequest.VerifiedPreview` imports those bytes even if the source later changes; the dialog never rereads source art or metadata.

`PrepareImport(request, CancellationToken)` and `PrepareRemove(request)` return opaque `IsoCustomObjectPlan` with proposed catalog, complete pack and issues, without disk writes. Removal's trailing optional `BuiltInPack` is required by integrated callers; legacy Remove wrappers may omit it. `Commit(plan, CancellationToken=default)` verifies the original catalog under the writer lock and publishes only after consumer preflight. Existing Import/Remove remain thin wrappers for local CLI/backwards compatibility. UI always uses the staged transaction.

`IIsoEditor.PreviewPack(pack)` checks current, saved, default and Undo/Redo documents without mutation. `IIsoEditorRuntime.PreviewEditorPack(pack)` checks live/pending layouts and actor/pet assets. The composition point synchronously preflights both consumers and prepares sheet decoding before catalog publication, then adopts the same pack on the owning UI thread. No consumer revision may change between preflight and adoption. Failure or cancellation before publication retains catalog, editor, runtime, palette and selection. Same-hash re-import preserves files and consumer revisions.

`IIsoEditor.GetPickingScene(camera)` supplies the cached authoritative current draft queue/masks, including navigation-invalid or runtime-pending drafts, in the live scene camera coordinates. HitTest never pairs a current draft with the previous published furniture queue. Preview candidates remain separate ghosts until committed.

`IIsoEditorRuntime.GetEditorSeatStatus()` returns only immutable seat ID and `IsoEditorSeatOccupancy` (`Free`, `Assigned`, `Away`); no names or agent IDs. Status is transient and excluded from saved layout/history. `AppliedEditorRevision` acknowledges the last fully applied valid editor revision. UI clears Applying when this acknowledgement reaches its requested revision, independently of layout reference identity. Invalid drafts cancel pending swaps, never publish invalid geometry, leave the live valid layout running and immediately clear Applying.

## 10. Historical handoff differences and preserved constraints

The differences below describe the original handoff. The merged base `9cec3a9` already supplies aggregate editor validation, explicit work seats, custom pack merging and the virtual computer adapter. Integration 1.1 connects them through the real storage resolver and composition; production and demo editor paths have no stub dependency. The legacy navigation, art, tracker and flat-mode constraints below still apply.

The approved historical slice names three desks, while the shipped pack and IsoOffice default now have twelve; Reset uses the shipped pack. IsoLayoutLoader.Default remains a three-seat helper. Root schema stays version1 despite historical “v6” tracker plans; Tracker currently exports flat v5 and has no iso consumer. Do not add iso tracker publication in this editor task.

Existing IsoLayoutLoader.Validate is fail-fast, allows 8..128 rooms, rejects isoEditorV1, treats all desk profiles as seats and checks every approach, while IsoOffice derives seats from `assetId=="iso/desk"` with no reload hook. Core must add editor aggregate validation/capability support and explicit-seat reload without weakening legacy validation or seated contact tests. Navigation retains legacy authored interactions/disabled desk approaches too.

The furniture convention's monitor36/chair-back28/TV38 values are historical; current v3 monitor top40, chair back21 and TV top48 govern. Its simple ground sort is refined by IsoFurnitureOrder's footprint/support topology; the item queue is authoritative. Seated production baking uses a separate per-pixel proxy depth `D=i+j+2z` in 1/16-tile units. This is **not** the runtime ground-depth formula and must not become an editor z offset. The seated cushion fit gate (SE/SW overhang at most 5px per side, set by the supervisor after chairfix2 made the cushion as wide as the backrest) is an existing art criterion; editor lanes must not change its thresholds.

Current pack loader has no public merge function and ignores authoring `decorAssemblies` when assembling IsoManifest; objects lane adds a narrow clone/merge hook, retaining cached compiled rigs/shared UI rather than duplicating them. Core wall catalog groups compiled `-edge-N` modules as §3.2. Current IsoApplication.Prepare ignores user iso layouts and `allowPreview`; UI wires the new Core storage resolver and isolated AppStorage root. Preserve explicit flat-only --layout and current separate IsoWindow, rather than following the older proposal to turn OfficeView into a mixed renderer.

The built-in computer is currently embedded desk art, with no standalone family; objects lane must deliver the virtual adapter and its subset contract before core's mounted-computer runtime acceptance. Core/UI can build immediately against stubs, but behavior acceptance waits for that adapter. Definitions in Editing are the frozen inter-lane API; report required signature changes to the supervisor instead of inventing alternate types.

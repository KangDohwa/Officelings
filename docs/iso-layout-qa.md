# ISO 사무실 12석 배치

10×10 방에 책상 두 개를 등지고 붙인 여섯 쌍을 배치했다. 각 쌍에서 맞닿는 면은 책상 뒤쪽이다. 의자와 다른 책상, 모니터와 라운지는 점유칸을 공유하지 않는다. 책상 쌍은 `j=1,4,7`에서 시작하고, 가운데 `i=4,j=1..6`은 한 칸 폭의 통로다. 하단 통로는 라운지와 책상 쌍의 양 끝을 돌아 연결된다.

## 참조 배치 보존

[iso-spec.md](iso-spec.md)의 세 책상 좌표는 명세에 적힌 검증용 예시다. `IsoLayoutLoader.Default`는 기존 `(2,2)/NW`, `(5,2)/NE`, `(4,5)/SW`와 연결 의자를 그대로 유지한다. 기존 접촉점·회전 테스트도 이 배치를 사용한다.

실제 기본 사무실과 pack `layout.json`은 아래 12석을 사용한다. 형식 버전, API, 투영, 접촉점, 시트와 아트는 유지했다.

| 책상 쌍 | 첫 책상 | 둘째 책상 |
| --- | --- | --- |
| 1–2 | `(2,1)` NE | `(2,2)` SW |
| 3–4 | `(7,1)` NW | `(8,1)` SE |
| 5–6 | `(2,4)` NE | `(2,5)` SW |
| 7–8 | `(6,4)` NW | `(7,4)` SE |
| 9–10 | `(5,7)` NW | `(6,7)` SE |
| 11–12 | `(8,7)` NE | `(8,8)` SW |

의자는 각 desk `front` 프로필의 approach에 놓이며, 작업자는 책상 전면의 반대 방향으로 모니터를 본다. Python 생성기는 시트 메타데이터에서 의자 위치·방향을 읽는다. 테스트에서 C# fixture와 pack의 모든 좌표·방향·연결, 바닥, 구역이 같은지 비교한다.

## 라운지와 벽면 가구

라운지는 `i=0..2,j=6..9`다. 소파 `(0,9)/NE`, 러그 `(0,7)/SW`, TV `(0,7)/SE`, 탁자 `(2,7)/SE`를 배치했다. TV와 탁자는 비차단 러그 위에 놓이고 작업 책상·의자는 러그 밖에 있다.

책장 `(0,0)`, 식물 `(0,2)`, 램프 `(0,3)`, 냉장고 `(0,5)`는 왼쪽 벽에, 커피 `(1,0)/SW`와 정수기 `(5,0)/SW`는 뒤쪽 벽에 놓인다. 냉장고를 작업석 옆 구석에서 빼고, 문 앞 `(0,4)`과 창 옆 `(4,0)`을 비워 두었다. 기존 문·창 벽 모듈과 20개 벽 구간은 유지했다. 체크 바닥은 뒤쪽 한 줄과 왼쪽 책장·식물 아래의 총 12칸이다.

책상 approach 12개와 다른 상호작용 4개가 문에서 도달 가능하다. 가구 차단칸은 37개, 탐색 가능한 바닥은 63칸이다. 의자 12개를 점유한 것으로 추가 차단해도 빈 바닥 51칸이 모두 연결되며, 각 좌석에 인접한 통로가 남는다. 고양이 시연 경로는 `(2,6)`에서 왼쪽 통로를 왕복하며 가구와 상호작용 approach를 피한다.

## 렌더와 병합

오프스크린 명령은 `--view iso --demo --smoke-test artifacts/iso-layout-final --smoke-tags --tags always`다. 빈 방, 3명, 12명 근무, 입퇴장, 데모, 고양이를 1×/2×/3×로 렌더한다. 대표 PNG는 `artifacts/iso-layout-final/iso-empty-2x.png`, `iso-three-2x.png`, `iso-twelve-working-2x.png`, `iso-arrival-02.0s-2x.png`, `iso-departure-22.0s-2x.png`, `iso-demo-24.0s-2x.png`다. 산출물은 커밋하지 않는다.

하단 `(9,9)` 의자의 원본 캔버스 여백까지 포함하면 장면 높이는 448px이다. 실제 바닥은 기존 640×320 투영 범위를 유지한다. 이름·카메라·가림 처리는 기존 렌더러가 맡는다. 입퇴장 중 움직이는 몸의 충돌 회피는 기존 엔진의 범위 밖이며, 이 변경은 경로 탐색과 정적 배치를 검증한다.

이 lane은 `tools/build_iso_pack.py --layout-only`로 **layout.json만** 재생성했다. 따라서 기존 `assets.json`의 `files` 목록에 적힌 layout 크기·SHA256은 이전 값이다. 런타임은 layout을 별도로 읽지만, 병합 후 packaging 담당자가 일반 pack 빌드로 이 파일 인덱스를 갱신해야 한다. 원본 시트·아트·해시는 수정하지 않았다. 합성 3인 acceptance fixture의 desk ID도 런타임의 기존 ordinal 좌석 순서(`desk-1,desk-10,desk-11`)에 맞췄다.
